# 2min 批量投递 + 无增量不发（0.9.6）

## 问题

- 消息间隔 **p10 6.6s / p50 20s / p90 90s**，最长连续 **151 条**（间隔 <2min）；单小时峰值 209 KB（≈10 万 tokens）。
- 每条消息都带完整状态镜像（431/624，69%），**纯短回执 0 条** —— 没有一条消息是「收到，结束」。
- 结果：两条会话各 compaction 2 次，且都落在最忙时段（12:02 / 00:46）。

## 需求

- **R1 批量窗口 2min**（D3）：非紧急消息进入窗口，合并为一条 envelope（携带 N 个 item），到期统一投递。
- **R2 直通**：`escalate` 与 `status='blocked'` **<10s** 直通，不进窗口。
- **R3 无增量不发**：本轮无新事实/无状态变化 → **只写 `collab_status`，不产生消息**；注入头只更新计数。
- **R4 窗口内去重**：同一 `thread + factID` 在窗口内合并为一条；同 thread 的重复回执合并。
- **R5 时效承诺**：整体仍 ≤5min（D11）；窗口 2min + 投递 + 处理留 3min 余量。
- **R6 可观测**：`metrics.median_gap_ms` 每日落库，用于验收。

## 验收

- [ ] 连发 10 条非紧急消息 → 收端在 ≤2min 内收到 **1 条合并消息**，item 数 = 10。
- [ ] `escalate` → <10s 收到，不等待窗口。
- [ ] 无增量回执 → 不产生消息；`collab_status` 可见状态更新。
- [ ] 窗口内同 thread + 同 factID → 合并为 1 条。
- [ ] 回放两会话序列：p50 间隔从 20s 提升到 **≥2min**，消息总量下降 ≥5 倍。
- [ ] 回归全绿；工具数不变（28）。
