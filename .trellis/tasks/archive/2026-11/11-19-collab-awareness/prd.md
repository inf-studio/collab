# PRD：协作自动感知（0.7 首要）

## 问题

会话 A 需要 B 协助时，目前必须**人**提醒 A「用 collab_handoff」；B 收到投递后也不一定知道「回执要 collab_reply / DONE|BLOCKED」。工具存在，但会话不知道何时、用哪个通道——**尤其是跨工作区**（实测链路 A(issues-wt) → B(mojoy-studio)）。

## 需求

- **R1 需求侧提示（双通道）**：`context` 注入追加**一行**，同时给出两种候选数量：

  ```
  协作：本工作区候选 N（collab_handoff） · 其它工作区候选 M（collab_broadcast，需提案）
  ```

  - N = 同工作区其它活跃会话数；M = **其它工作区**活跃会话数（按 location 聚合，去重）；
  - 条件：非 protected、`N+M ≥ 1`、当前会话**没有**未闭环交接、10 分钟内未提示过；
  - 长度 ≤140 字；与 `maxInject` 共享注入预算（超限时本行先让位给交接/队列行）。
- **R2 承接侧协议头**：收到的交接注入块**首行**固定两行：`你是承接方（bid/thread）` + `完成/阻塞后必须回执：collab_reply {threadID}`（跨工作区再加一句 `或 [handoff] DONE|BLOCKED <bid>`）。
- **R3 成本上界**：跨工作区计数需要宿主会话列表；**每 10 分钟最多查一次**（进程内缓存，按会话键），查不到就省略 M 而不是报错。
- **R4 只读**：提示只是注入行，不写记录、不投递、不建 thread。
- **R5 关闭**：`awareness: "line" | "off"`（默认 `line`），关闭后 0 行。

## 约束

- 不猜测「该找谁」——只给数量与通道，选人仍由 `collab_handoff` 打分或人指定；
- protected 会话不提示（它只能靠队列/被问询）；
- 不改变既有注入行的顺序与上限语义。

## 验收

- [ ] 同工作区 2 会话 + 其它工作区 3 会话 → 行内容 `本工作区候选 1 · 其它工作区候选 3`；
- [ ] 只有跨工作区（N=0, M≥1）→ 仍出现，标明只有 `collab_broadcast`；
- [ ] 已有一笔未闭环交接 → 不出现；
- [ ] protected → 不出现；`awareness:"off"` → 不出现；
- [ ] 10 分钟内重复 context → 只出现一次；跨工作区列表**只查一次**（用假宿主计数）；
- [ ] 宿主列表不可用 → 只显示 N，不抛错；
- [ ] 承接方注入首行含「承接方」+ 回执方式（跨工作区含 `[handoff] DONE|BLOCKED`）；
- [ ] 回归全绿（注入行数/顺序断言）。

## 非目标

- 不自动调用 handoff/broadcast；
- 不注入候选清单全文（只给数量 + `collab_list`）；
- 不做跨机器。
